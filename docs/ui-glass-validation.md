# UI glass validation notes

The original user screenshot is a flat, sharp-cornered cyan HUD with uniform dark panels and no material depth. The first generated preview accidentally showed the API dialog and exposed obsolete local-model fields. The second preview showed the redesigned main window with a layered midnight backdrop, differentiated glass surfaces, highlighted pane edges, interactive button surfaces, and a central layered lens/orb. The API dialog was then cleaned to contain Gemini and OpenRouter fields only. A headless Tk construction smoke test passes under Xvfb; actual Windows DWM Acrylic/Mica blur, native font rasterization, and physical-device behavior remain Windows-only.
The rounded canvas control experiment confirms rounded silhouettes render, but the first implementation is visually too scalloped and the header action grid clips on the current width. The next pass must use smoother rounded rectangles, avoid oversized three-column header actions, and give the hero shell more intentional spacing and depth. It is not ready for release.
The latest preview now has clean rounded left/right cards and smooth pill controls. It is materially different from the failed flat rectangular HUD, but the center stage remains a conventional rectangular surface and the header is still dense. Native DWM composition is wired for Windows, while Linux headless preview cannot demonstrate Acrylic/Mica. This is a substantial improvement but should not be described as full native liquid glass without Windows verification.
